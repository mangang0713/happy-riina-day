# H1-KEY Activity Archive

리이나의 생일을 축하하며 H1-KEY의 활동 기록을 보존하는 팬 아카이브입니다. 첫 화면에서 생일 소개를 보고, 지도에서 장소와 날짜를 따라 활동 기록을 탐색할 수 있습니다.

각 장소의 스케줄과 무대 기록을 연결해, 활동의 발자취를 한눈에 살펴보고 개별 공연의 추억을 다시 확인하는 것을 목표로 합니다.

> **개발 중인 프로젝트입니다.** 사용자가 정리한 2026년 일정 111건(2026-02-21~2026-10-28)을 등록했습니다. 이 중 99건은 세트리스트 확인, 12건은 곡 공연 없음 확인으로 구분했습니다. X 게시물 본문 날짜를 우선 대조하고 사용자가 지정한 예외를 반영해 게시물 109건(사진 총 287장)을 일정별 미리보기로 연결했습니다. 사진 원본 게시물은 중복 표시하지 않고, 영상 게시물은 X 임베드로 표시합니다. 장소 82곳의 좌표를 지도에 표시하며, 넓은 장소는 탐색용 대표 지점을 사용합니다.

## 테스트 배포

- [공개 테스트 사이트](https://mangang0713.github.io/happy-riina-day/) — 링크가 있는 누구나 로그인 없이 접근할 수 있습니다.
- 현재는 기능 확인을 위한 테스트 배포입니다. 사진과 영상은 X의 외부 리소스를 사용하므로 X의 로딩 정책이나 네트워크 상태에 따라 표시가 달라질 수 있습니다.
- 정식 운영 전에는 최종 도메인·배포 환경과 미디어 공개 범위 및 권리 확인을 진행합니다.

첫 접속 화면은 사진 자료가 준비되기 전까지 소개용 그래픽과 준비 중 안내를 표시합니다. 지도 탐색은 상단의 **지도** 메뉴 또는 랜딩 화면의 **지금 확인하기**에서 시작합니다.

## 주요 기능

### 지도 탐색

- 대한민국 중심의 **2D 인터랙티브 지도** (MapLibre GL JS)
- 가까운 **여러 장소를 클러스터로 묶고**, 확대하면 개별 장소 마커로 분리
- 초기 축소 화면에서 수도권 장소는 하나의 클러스터로 보일 수 있으며, 클러스터를 눌러 확대해 개별 장소를 탐색
- 단일 스케줄 장소는 일반 핀, 여러 일정이 있는 장소는 **일정 개수가 표시된 핀**으로 구분
- 장소를 선택하면 카메라가 해당 위치로 이동하고, 상세를 닫으면 **선택한 장소를 중심으로 이전 확대 수준·방향 복원**
- **처음으로** 버튼으로 대한민국 초기 지도 복귀, 모바일 크기에 따른 버튼 UI 조정
- **지역 이동** 메뉴에서 현재 지역을 제외한 일정 등록 국가로 이동. 한국·중국·일본 등 다른 활동 지역을 선택할 수 있고, 카메라가 축소된 뒤 해당 지역의 등록 장소로 이동해 다시 확대
- **시간순으로 보기**에서 2026-02-21부터 현재까지의 일정을 순서대로 재생. 이동하는 차를 중심으로 카메라가 부드럽게 따라가고, 도착한 장소마다 일정 마커가 누적 표시됨
- 재생 중에는 날짜만 간결하게 표시하고, 일시정지하면 현재 행사명과 장소를 확인 가능. 이동 중 카메라와 차를 함께 멈추며 재생 시 현재 목적지까지 이어서 이동
- 시간순 탐방에는 건너뛰기 슬라이더나 전체 일정 위치 카운터를 두지 않아, 재생 순서와 마커 누적 흐름을 유지
- 영상통화 일정 패널은 목록 바깥을 누르면 닫히며, 지도와 별도로 날짜순 기록을 탐색
- **전체 기록** 패널에서 모든 행사를 날짜·국가·형식·행사명·곡·장소로 검색
- **곡별 기록**에서 확인 완료·부분 확인 세트리스트로부터 곡이 등장한 일정 수를 자동 계산

### 생일 랜딩 페이지

- `/`에서 생일 인사, 준비 중인 사진·이야기 소개, 아카이브 이동 버튼을 표시
- 작은 화면에서는 세로 섹션을 스크롤하며 차례로 확인하고, 동작 줄이기 설정을 존중

### 스케줄 및 세트리스트

- 장소별 스케줄 **1건은 상세로 바로 이동**, 여러 건은 날짜별 목록에서 선택
- 상세 정보는 행사 정보·세트리스트·사진·영상 탭으로 나누어 확인
- 행사 상세 페이지에서 날짜·장소와 확인된 시작 시간을 보조 정보로 표시. 같은 날짜 행사 순서는 데이터 검증용으로 관리하며 화면에는 표시하지 않음
- **세트리스트를 공연 순서대로 표시**하고 곡 ID를 통해 곡 정보를 연결
- 공식 계정 미디어는 행사별 그룹 사진·개인 사진·릴스로 분류하며, 사진은 저장소의 로컬 정적 파일로 연결
- 전체 일정 검색 결과에서 지도에 표시되지 않는 영상통화·장소 미확인 일정도 열람
- 세트리스트 **확인 완료 / 일부 확인 / 임시 기본 입력 / 미확인 / 공연 곡 없음** 상태 구분
- 곡별 통계는 확인된 곡만 집계하며, 일부 확인 일정은 확인 가능한 최소 기록으로 표시
- 전체 기록의 행사 상세에서 좋아요 수와 최근 후기를 확인하고, 기존 일정 상세 페이지로 이동해 좋아요·후기를 이용
- 장소·일정·곡은 TypeScript 데이터 파일에서 계속 수정·추가

## 기술 스택

- **Frontend:** React, TypeScript, Vite, Tailwind CSS v4
- **Typography:** Pretendard Variable dynamic subset webfont (with system-font fallback)
- **Map:** MapLibre GL JS
- **Map style / tiles:** OpenFreeMap (현재 개발용 스타일)
- **Code quality:** ESLint, Prettier

Tailwind 유틸리티는 공유 레이아웃과 생일 랜딩 페이지부터 적용하고 있습니다. MapLibre 동적 마커·Popup과 커뮤니티 폼처럼 세부 상태가 많은 화면은 기존 CSS를 유지하며 단계적으로 전환합니다.

## 실행 방법

Node.js와 npm이 설치된 환경에서:

```bash
npm install
npm run dev
```

터미널에 표시되는 로컬 주소(기본값: `http://localhost:5173`)에서 확인할 수 있습니다.

```bash
npm run build
npm run lint
npm run format:check
npm run preview
```

- `build`: TypeScript 검사 및 배포용 빌드
- `lint`: ESLint 코드 검사
- `format`: Prettier로 코드 포맷 적용
- `format:check`: 포맷 변경 없이 Prettier 검사
- `preview`: 빌드 결과 로컬 미리보기

브라우저 경로 라우팅을 사용합니다. `/`는 생일 랜딩 페이지, `/archive`는 지도 아카이브이며 각 페이지 코드는 필요한 때 불러옵니다. GitHub Pages의 하위 경로 직접 접속과 새로고침은 `404.html`에서 앱 경로를 복원해 처리합니다. 기존 `#/...` 링크도 열면 새 경로로 정리됩니다. 지도 클러스터와 장소 마커는 MapLibre 레이어로 렌더링해 지도 확대·이동과 같은 프레임에서 위치와 크기가 바뀌도록 합니다.

지도 생명주기와 카메라 흐름은 `ArchiveMap.tsx`에서 조율하고, 마커 레이어 정의는 `locationMarkerLayers.ts`, 지도용 데이터 계산은 `archiveMapData.ts`, 탐색 메뉴 UI는 `ArchiveExplorerControls.tsx`, 시간순 탐방 동작은 `timeTravelController.ts`, 장소 이동은 `regionNavigationController.ts`가 맡습니다. 방명록 페이지는 목록과 사용자 권한 상태를 연결하고, 작성 폼과 신고 대화상자는 별도 컴포넌트가 담당합니다. Edge Function은 요청 진입점과 공통 HTTP 도구, 사진 처리, 운영자 조정·만료 정리로 나눴습니다. 공통 HTTP 도구는 Deno 단위 테스트로 검사합니다. Popup 콘텐츠와 탐색 UI의 스타일은 각각 해당 컴포넌트 파일 옆에 둡니다. `schedules.ts`, `locations.ts`, `schedulePhotos.ts`는 길지만 각각 원본 데이터 목록이라 가져오기 도구 호환성을 위해 한 파일에서 계속 편집할 수 있도록 유지합니다.

장소와 스케줄은 **1:N 관계**로 관리하며, 세트리스트에는 곡 제목 대신 곡 ID를 저장합니다.

### 공식 계정 사진 추가·분류

공식 계정 사진은 게시물 본문에 적힌 행사 날짜를 기준으로 `public/media/official/<YYYY-MM-DD>/group/` 또는 `public/media/official/<YYYY-MM-DD>/individual/`에 넣습니다. `src/data/officialScheduleMedia.ts`에서 해당 일정 ID의 `officialGroupPhotos` 또는 `officialIndividualPhotos` 배열에 연결합니다. 파일 경로는 빌드 환경의 기본 경로를 자동으로 반영하므로 로컬과 GitHub Pages에서 같은 데이터 목록을 사용할 수 있습니다. 릴스는 영상 파일을 저장하지 않고 공식 Instagram 게시물 링크를 `officialReels`에 기록합니다. 각 분류의 자료가 연결되면 기존 지도 상세에 해당 탭이 나타나며, 자료가 없는 분류는 탭을 숨깁니다.

`public/`의 파일은 빌드 결과에 포함되어 공개 사이트에서 누구나 열 수 있습니다. 실제 자료를 추가할 때는 공개해도 되는 파일인지 확인하고, 사진은 웹용으로 크기를 줄인 파일을 사용하세요. 파일 이름은 폴더 안에서 `01.webp`, `02.webp`처럼 순서를 알 수 있게 정하면 됩니다.

### 온라인 일정과 지도 위치

- 영상통화 팬사인회처럼 기록과 날짜가 확인된 온라인 행사도 아카이브 일정으로 보존합니다.
- 온라인 일정에는 실제 장소가 없으므로 임의의 `Location`이나 좌표를 만들지 않습니다. `locationId`가 연결된 일정만 지도 마커와 장소별 클러스터에 표시합니다.
- 영상통화 일정은 지도 위의 별도 버튼에서 날짜순 목록으로 확인합니다. 지도에는 실제 `Location`에 연결된 일정만 나타나며, 목록에서 일정을 선택하면 날짜·형식·시간·세트리스트 상세를 볼 수 있습니다.
- 녹화 영상 파일과 공개 범위, 저장 위치는 별도로 정한 뒤 연결합니다. 현재 데이터 모델에는 외부 미디어 URL 필드만 있습니다.
- 장소가 없는 일정 중 `eventFormat`이 `online`인 영상통화 기록을 이 목록에 표시합니다. 장소를 확인하지 못한 대면 일정은 영상통화로 잘못 분류하지 않도록 별도 검토 대상으로 둡니다.

현재 영상통화 목록에는 실제 기록이 확인된 일정 5건이 들어 있습니다. 영상 녹화 파일과 미디어 연결은 아직 진행하지 않았습니다.

### 일정 데이터를 계속 추가하는 방법

현재 데이터 원본은 `src/data/locations.ts`, `src/data/schedules.ts`, `src/data/songs.ts`의 TypeScript 목록입니다. 새 일정은 `schedules.ts`에 고유 ID와 확인된 날짜를 추가하고, 실제 장소와 주소가 확인되면 기존 또는 새 `locationId`를 연결합니다. 아직 좌표가 확인되지 않은 장소도 이름·주소·일정 관계를 보존하며, 좌표가 추가되면 지도에 표시됩니다. 세트리스트는 `songs.ts`의 곡 ID를 공연 순서대로 참조합니다. 데이터 모듈은 ID, 장소·곡 참조, 같은 날 순서 중복을 검사합니다.

Google Sheets에서 **확정 일정** 탭을 CSV로 다운로드한 뒤 아래 명령으로 먼저 검증할 수 있습니다. 미리보기는 코드를 수정하지 않습니다. 검증을 통과하고 변경 내용을 확인한 다음 `--write`를 붙이면 일정과 새 곡 제목을 TypeScript 데이터에 반영합니다. 기존 장소와 일치하지 않는 새 장소도 시트의 자동 검색 주소·좌표 후보를 확인 완료로 표시하면 가져오기 도구가 `locations.ts`에 추가합니다.

Apps Script는 시트의 주소·좌표 후보를 채우며 웹 앱 데이터를 실시간 동기화하지 않습니다. 시트를 수정한 뒤 최신 전체 CSV를 내려받아 미리보기와 검증을 통과시키고, `--write`로 앱 데이터 파일을 갱신해야 지도에 반영됩니다. 전체 가져오기는 미완성 행이나 검토 대기 장소가 있으면 중단하므로 먼저 해당 행을 보완해 주세요.

```bash
npm run data:import -- --input path/to/schedules.csv
npm run data:import -- --input path/to/schedules.csv --write
```

### 새 장소 주소·좌표 후보 자동 검색

**확정 일정** 탭의 `장소명` 또는 `장소 주소 / 홀 이름`을 입력하면 연결된 Apps Script가 주소 후보, `[경도, 위도]` 좌표 후보, 확인 상태를 K:M 열에 기록하도록 설정할 수 있습니다. Apps Script 편집기에 `scripts/sheets-place-geocoder.gs` 내용을 붙여넣고 `installPlaceLookupTrigger`를 한 번 실행해 권한을 승인하면, 이후 장소 입력 시 자동 검색됩니다. 자동 검색 결과는 `검토 필요`로 표시되므로 주소와 지도 지점을 확인한 뒤 `장소 좌표 확인 상태`를 `확인 완료`로 바꿔 주세요.

CSV 가져오기는 확인 완료된 새 장소를 `locations.ts`에 추가하고, 같은 행의 일정을 그 장소에 연결합니다. 확인되지 않은 검색 결과나 유효하지 않은 좌표는 가져오기를 중단합니다. Apps Script 소스는 `scripts/sheets-place-geocoder.gs`에서 관리하며, Google Apps Script Maps Geocoder의 일일 사용량 제한이 적용됩니다.

반영 후에는 `npm run build`와 `npm run lint`를 실행해 주세요. 가져오기는 행사명·날짜를 기준으로 기존 일정 ID와 행사 형식을 유지합니다. 곡 제목은 `->`, `→`, 또는 공백으로 구분한 하이픈으로 나누며, 시트의 세트리스트 상태(전체 확인·일부 확인·임시·미확인·곡 공연 없음)를 그대로 구분합니다. 장소명 열의 `ㅇ` 표시는 영상통화 일정으로 처리하며 지도 장소나 좌표를 만들지 않습니다.

현재 데이터는 2026-02-21~2026-10-28의 일정 111건과 곡 13곡입니다. 세트리스트 상태는 전체 확인 99건(`known`), 곡 공연 없음 12건(`none`)입니다. 영상통화 5건은 장소 없이 보존하고, 장소 정보가 없는 대면 일정 1건도 기록에서 제외하지 않았습니다. 장소 82곳은 지도 표시용 좌표가 있습니다. 넓은 행사장·캠퍼스·광장은 실제 무대가 아닌 탐색용 대표 지점일 수 있습니다. 새 일정과 세트리스트는 원본 시트 검토 후 기존 TypeScript 데이터에 반영합니다.

## 추가 페이지와 Supabase

생일 랜딩 화면에서 축하의 맥락을 소개하고, 지도는 아카이브의 중심 탐색 화면으로 제공합니다. 방명록, 일정 좋아요·후기, 계정, 신고 검토, 운영 설정은 별도 페이지로 연결해 기능을 확장할 수 있습니다.

Supabase 프로젝트에 DB 마이그레이션과 `community-api` Edge Function을 적용했고, Cloudflare Turnstile도 연결했습니다. GitHub Pages 빌드는 저장소 Actions 변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_TURNSTILE_SITE_KEY`를 사용합니다. URL, publishable key, Turnstile site key는 브라우저에서 사용되는 공개 설정값이며, service-role key와 Turnstile secret key는 서버에만 둡니다. 2026-10-21에는 공개 배포본에서 방명록 조회와 게시된 글 표시를 확인했습니다. 배포본의 로그인·작성·수정·삭제·신고와 관리자 권한은 출시 전 다시 점검해야 합니다. 설정이나 커뮤니티 기능에 문제가 있어도 지도와 정적 일정 데이터는 계속 작동합니다.

장소·일정·곡은 스프레드시트에서 검토하고 TypeScript 정적 데이터로 빌드합니다. 계정과 사용자 콘텐츠만 Supabase에 저장해 공개 일정 조회가 데이터베이스 사용량을 늘리지 않도록 했습니다. 사용자 사진은 비공개 Storage를 사용하며, 계정당 총 10장·10MB, 글당 3장, 파일당 1MB, 전체 800MB 한도를 서버에서 확인하도록 설계했습니다. 글 작성 전 개인정보 안내와 공개 동의를 받습니다.

프로젝트 연결, OAuth·Turnstile 설정, 관리자 권한, 사용량 중단 기준은 [Supabase 설정 및 운영 안내](supabase/README.md)에 정리했습니다. 개인정보 안내에는 운영자 문의 계정 `@hessxl_`와 2027년 12월 31일 이후 서비스 데이터 폐기 예정일을 반영했습니다. 공개 운영 전 실제 처리 흐름과 정책의 일치 여부, 로그인·작성·수정·삭제·신고·관리 권한을 검증해야 합니다.
